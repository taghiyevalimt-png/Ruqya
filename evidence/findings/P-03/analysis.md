# P-03 — кадры > 50 мс при выезде окна «Yeni qəbul» (первое открытие после загрузки)

Профиль: CPU ×4 (CDP), 412×823 DPR 2, Chrome через playwright-core; видеокарта этого ПК — Intel HD Graphics (0x0A16, D3D11).
Проверка: `node tests/perf/frames.js <out.json> 5` (оценивает прокрутку, выезд окна — кадры между animationstart и animationend — и закрытие).

| Что | Результат | Файл |
|---|---|---|
| Прокрутка календаря, статистики, пациентов | 0 кадров > 50 мс во всех прогонах | before.txt, after.txt |
| Второе открытие окна (выезд) | 0 кадров > 50 мс (5/5) | after.txt |
| Первое открытие окна (выезд) | 1 кадр 132–140 мс в каждом прогоне — НЕ ПРОЙДЕНО | after.txt |

Причины (проверил запуском, трассировка и замеры):
1. Разовая подготовка браузером полей формы при первом показе (поле даты 29 мс, текстовое поле 15 мс, заголовок 22 мс … при CPU ×4) — ≈ 160 мс в кадре перед выездом; при повторных открытиях 17–26 мс.
2. Догрузка кириллической части шрифта (имена в подсказках) в момент открытия → полная перерисовка окна. **Исправлено**: шрифт загружается заранее в свободное время (`fontsSoon`, index.html); запрос при открытии исчез (проверка: запросы при открытии `[]`).
3. Растеризация окна видеокартой ≈ 130 мс (GPUTask) в первом кадре выезда; около половины — тень окна: без тени 54–59 мс, с облегчённой тенью 123–137 мс (shadow-experiment.txt).

Попытки, отменённые как не давшие доказанного улучшения: заранее «прогреть» форму в невидимом блоке (нестабильно); рисовать окно сначала в стартовой позиции выезда (attempt-pre-frame.txt: медиана 118 мс против 93 до).
Ни одна из правок, кроме видимого изменения (убрать тень), не даёт ≤ 50 мс, и даже без тени остаётся 54–59 мс → находка остаётся открытой, вынесена в RISK_REGISTER.md. На реальном среднем телефоне не проверено (нет устройства) — НЕ ПРОВЕРЕНО.
