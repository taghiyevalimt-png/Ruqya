# HANDOFF — приложение записи «Mərkəz» (Ruqya)

Документ для разработчика, который не видел историю создания. Состояние на 2026-11-14, снимок кода — тег `audit-start-20261114` (коммит `aba5ab8`) и последующие коммиты аудита в ветке `main`.

## 1. Что это и для кого
Приложение записи и статистики одного центра руқья/хиджамы в Баку. Пользуются сотрудники центра (не пациенты): на телефонах (iPhone — через Safari «на экран Домой», Android — APK-оболочка) и на компьютерах в браузере.

- **Qəbullar (календарь):** колонка на каждого специалиста, сеансы 30–180 мин в окне 08:00–24:00, перерывы, список и сетка, подтверждение прихода ✅/✅✅.
- **Statistika:** записи по дням, недели (пятница–четверг), месяцы (с первой пятницы месяца); таблицы продаж агентов, денег и товаров (деньги — только админ), правка чисел, выгрузка Excel (админ).
- **Kassa:** продажи товаров и расходы по дням.
- **Pasiyentlər:** пациенты, собранные из записей (по телефону), история визитов.
- **Ayarlar:** специалисты, перерывы, сотрудники и роли, журнал изменений с восстановлением удалённого (админ), вид (ширина/высота блоков, тема), язык, аккаунт.
- **Android-виджет:** месяц с именами.

Языки: азербайджанский (по умолчанию) и русский. Часовой пояс всегда Asia/Baku.

## 2. Какие данные хранятся
| Таблица | Что | Персональные данные |
|---|---|---|
| `appts` | записи: специалист, дата, время, длительность, имя и телефон пациента, цена, заметка, статус, подтверждение, кто записал | да (имя, телефон, свободная заметка) |
| `readers` | специалисты (колонки): имя, цвет, архив; цена/доля — закрыты для API | имена сотрудников |
| `staff` | аккаунты сотрудников: имя, роль, желаемая роль | имена сотрудников |
| `breaks` | перерывы | нет |
| `expenses`, `product_sales` | касса: суммы, названия, кто внёс | нет |
| `stat_edits` | ручные правки чисел статистики | нет |
| `services` | старый список услуг (не используется) | нет |
| `audit_log` | журнал всех изменений (старая и новая версия строки), хранится 2 года + 1 день | да (копии записей) |
| `auth.users` (Supabase Auth) | e-mail и хеш пароля сотрудников | e-mail сотрудников |

На устройстве (localStorage): сессия Supabase; `ruqya.cache.v1` — копия загруженных данных для мгновенного старта (удаляется при выходе); настройки `ruqya.lang/theme/view/sel/hour/colw/setsec/stsec`.

## 3. Технологии
- Веб-приложение: один файл `index.html`, ES5 без сборки и фреймворков (работает на старых Android/iOS).
- `vendor/supabase-2.45.4.js` — локальная копия supabase-js (MIT). `vendor/fonts/` — шрифты Golos Text и Onest (SIL OFL 1.1).
- Безопасность страницы: CSP в `<meta>`, inline-скрипты разрешены только по SHA-256 (`tools/csp.py`).
- Бэкенд: Supabase (PostgreSQL 17, RLS, Auth e-mail+пароль, Realtime). Регистрация закрыта.
- Хостинг: GitHub Pages, репозиторий `taghiyevalimt-png/Ruqya` (публичный), ветка `main`, корень.
- Android: Java, minSdk 21, WebView, загружает опубликованную страницу; виджет месяца.
- CI (GitHub Actions): `apk.yml` (сборка APK), `apk-release-check.yml`, `widget-check.yml`, `vendor.yml` (supabase-js), `vendor-fonts.yml` (шрифты), `keepalive.yml` (не даёт бесплатной базе уснуть), `audit-probe.yml` (внешние проверки только на чтение), `backup.yml` (резервные копии — см. `docs/BACKUP.md`).

## 5. Роли и права (проверяются в базе через RLS)
| Роль | Как назначается | Что может |
|---|---|---|
| Владелец | фиксированный id в функции `ruqya_is_admin()` | всё; роль не меняется |
| Админ | `staff.role='admin'` (назначает админ) | всё: специалисты, перерывы, сотрудники, журнал и восстановление, деньги, Excel, цвета |
| Агент продаж | `staff.role='agent'` | все записи календаря; меняет/удаляет только свои записи (подтверждать может любые); своя статистика; своя касса |
| Специалист | `staff.role='specialist'` (привязка к колонке по имени) | видит только свои сеансы; подтверждает; без денег и кассы |
| Ожидает роль | есть аккаунт, нет роли | только экран «Hesab» |
| Без входа | — | ничего (проверено пробой: 0 строк/401) |

Правила в базе (живые): `appts` — `ruqya_sees_all() OR reader_id IN ruqya_my_readers()`; владелец/админ для изменения — триггер `ruqya_appt_owner`; `expenses`/`product_sales` — админ или свои строки; `stat_edits` — админ или свои; `readers` — читать могут все вошедшие (кроме колонок цены/доли), менять — админ; `breaks` — читать с ролью, менять `ruqya_can_breaks()`; `staff` — своя строка + админ; `audit_log` — только админ, писать никто (только триггер). Ограничения: длины полей, формат времени, пересечения сеансов (`ruqya_no_overlap`), лимит изменений 300/ч и 1 МБ/ч, 8 МБ/сутки на человека (`ruqya_throttle`).

## 6. Внешние сервисы и настройки (имена, без значений)
- Supabase: URL проекта и публикуемый ключ — в `index.html` (`SB_URL`, `SB_KEY`; ключ публичный по замыслу, защита — RLS). Для переноса — `tools/configure.py` и `.env.example`.
- Секреты GitHub Actions: `ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASS`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASS` (подпись APK), `SUPABASE_DB_URL`, `BACKUP_PASSPHRASE` (резервные копии).
- Ссылки `wa.me` и `tel:` для связи с пациентом.
- Аккаунты: проект Supabase и репозиторий GitHub принадлежат владельцу (`taghiyevalimt-png`). Домена нет (адрес github.io).

## 7. Запуск, тесты, публикация
- Локально: любой статический веб-сервер из корня репозитория.
- Тесты (Playwright + мок Supabase) и тесты базы (локальный PostgreSQL) — в архиве аудита, команда запуска — `tests/run-all.sh` (см. раздел тестов в архиве).
- Публикация веба: `./publish.sh "сообщение"` → GitHub Pages примерно за минуту.
- APK: любой push в `android/**` запускает `apk.yml` → релиз `Ruqya.apk`.
- Изменения базы: SQL-файл из `sql/` запускает владелец в Supabase → SQL Editor (у приложения нет ключа, способного менять схему).

## 8. Важные решения
- Сеанс считается успешным, когда его время прошло; удаление убирает его из всех итогов.
- Неделя — пятница–четверг; месяц — с первой пятницы.
- Данные хранятся минимум 2 года (требование руководства).
- Размер блоков календаря выбирается только в настройках (жесты убраны по просьбе владельца).
- Деньги видят только админы, в том числе на уровне базы.
- Схема базы меняется только SQL-файлами, которые запускает владелец.
