## 4. Блокирующие условия для государственного заказчика (решает владелец, код не решит)
1. **Платный тариф Supabase или собственный сервер с SLA.** Бесплатный проект приостанавливается через 7 дней без обращений, логи ~1 сутки, нет SLA; лимит 500 МБ (ST-2, A6-R2).
2. **Хостинг вне GitHub Pages** с HTTP-заголовками безопасности (HSTS, frame-ancestors, Permissions-Policy, X-Content-Type-Options). Готовые настройки: `deploy/nginx.conf`, `deploy/merkez-headers.conf` (сверены: дополняют CSP из `<meta>`) (S-01).
3. **Приватный репозиторий.** Сейчас публичный: в нём полная схема, политики доступа, манифесты копий, публичный DR-ключ (B-14). Секретов нет (проверено по всей истории).
4. **2FA для админов** (S-02). План: Supabase Auth MFA (TOTP): экран кода после входа (`auth.mfa.challenge/verify`), привязка в «Hesab» (`auth.mfa.enroll`, QR), требование `aal2` для админов в `private.ruqya_is_admin()`; затронуты: вход, «Ayarlar → Hesab», функция is_admin, тесты 02/18/21; оценка ~1 рабочий день.
5. **Автовыход ≤ 12 ч** (S-09): подготовлено (`IDLE_12H`), включается одной строкой + виджет + APK.
6. **Место хранения персональных данных:** eu-west-3 (Франция) — трансграничная передача; вопрос юристу заказчика (DATA_MAP.md).
7. **Вторая независимая площадка для резервных копий** (сейчас только GitHub Actions, 35 дней) (A6-R3).
8. **Договор на сопровождение** (чек-лист — раздел 6).
9. **Защита от утёкших паролей** выключена — включить: Supabase → Authentication → Sign In / Providers → Email → Prevent use of leaked passwords (Management API отсюда недоступен).

- **Ежемесячно:** Supabase Advisors (security, performance) — новых нет; размер базы против лимита; `cd tests && npm audit`; логи Auth (5xx, неудачные входы).
