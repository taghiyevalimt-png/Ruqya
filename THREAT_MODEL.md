# THREAT_MODEL — модель угроз (STRIDE)

## Движение данных и границы доверия
```
 [Сотрудник: телефон/ПК]  --HTTPS-->  [GitHub Pages: index.html, vendor/*]          (граница 1: интернет → статический хостинг)
        |  браузер / WebView (CSP: скрипты только свои по хешам; connect только к Supabase)
        |--HTTPS + JWT (publishable key + токен пользователя)-->  [Supabase API: PostgREST /rest/v1, Auth /auth/v1, Realtime wss]   (граница 2)
        |                                                              |  роль anon/authenticated, RLS, триггеры, SECURITY DEFINER функции
        |                                                              v
        |                                                     [PostgreSQL 17: public.*, auth.*]   (граница 3: API → БД, проверка прав в БД)
        |--tel:/wa.me (по нажатию)--> [телефон / WhatsApp]                      (граница 4: данные пациента уходят в сторонний мессенджер по действию пользователя)
 [GitHub Actions: backup, dr-export, keepalive, apk]  --DB URL с паролем (секрет)--> [PostgreSQL]     (граница 5: CI с полным доступом к БД)
        └--артефакты (зашифрованы)--> [хранилище артефактов GitHub] --> [владелец: ПК/флешка]
 [Владелец] --панель Supabase / GitHub (вход через GitHub)--> всё                                (граница 6: аккаунты владельца)
```

## Угрозы по элементам
| Элемент | STRIDE | Угроза | Защита | Чем подтверждено |
|---|---|---|---|---|
| Вход (Supabase Auth) | S | подбор пароля сотрудника | пароли задаёт админ; ограничение частоты входа Supabase; регистрация закрыта | T-33 (`disable_signup:true`); перебор — защита поставщика, не проверено запуском (риск R-…) |
| Вход | S | кража токена с оставленного телефона | автовыход через 12 ч без касаний, выход во всех вкладках | T-09, T-08 |
| Вход | S | вход без 2FA | — | находка: двухфакторного входа нет |
| API | T | изменение чужих записей прямым запросом | RLS + триггер `ruqya_appt_owner` | T-27 (матрица), T-28 (X-02, X-21) |
| API | T | подделка автора (`created_by`) | триггер `ruqya_stamp` | T-28 X-01, X-02; мутация M-07 поймана |
| API | T | присвоение себе роли | триггер `ruqya_staff_guard`, политики staff | T-28 X-06, X-07; мутация M-06 поймана |
| API | R | отказ от авторства изменений | журнал `audit_log` (триггер, писать в журнал не может никто) | T-28 X-18, X-19; T-27 audit_log |
| API | R | вход/неудачный вход не в журнале приложения | только логи Supabase Auth (короткий срок хранения) | находка |
| API | I | чтение чужих данных (специалист — чужих колонок, агент — чужой кассы) | RLS | T-27, T-28 X-03, X-04, X-16 |
| API | I | цена/доля специалистов | права на столбцы `readers` | T-28 X-09; мутация M-09 поймана |
| API | I | анонимный доступ | anon без политик; функции отозваны у anon | T-28 X-13, X-14 |
| API | D | заполнение базы мусором | лимиты длины полей, 300 изменений/ч и 1 МБ/ч, 8 МБ/сутки на человека | T-28 X-24, X-27; мутация M-12 поймана |
| API | E | вызов служебных функций (восстановление, обезличивание, цвет) | проверка `ruqya_is_admin()` внутри SECURITY DEFINER функций, `search_path` задан | T-28 X-10..X-12; мутации M-02, M-10 пойманы |
| API | I | обход RLS через `private.ruqya_visit_ids` (SECURITY DEFINER, P-04): узнать id чужих записей | схема `private` не открыта через API (PostgREST отдаёт только `public`); функция возвращает только id, сами строки `ruqya_hist_visits` читает с правами пользователя (RLS); у anon нет прав | X-28…X-32, тест 92-visits-access |
| Страница | T/E | XSS через имя/заметку пациента | экранирование `esc()` при выводе; CSP без inline-скриптов | T-35 |
| Страница | T | встраивание в чужой сайт (clickjacking) | скрипт выхода из чужой рамки; заголовок запрета на GitHub Pages задать нельзя | T-34; находка |
| Страница | I | данные на потерянном телефоне | копия ≤ 7 дней, черновик ≤ 2 дней, стираются при выходе/автовыходе | T-09; остаточный риск |
| Хостинг | T | подмена кода на GitHub Pages (взлом аккаунта GitHub) | 2FA на аккаунте (у владельца), контрольные суммы опубликованного | T-54; «Нужно от владельца» |
| CI | I/E | утечка `SUPABASE_DB_URL` из Actions | секрет, маскирование, только workflow_dispatch/schedule на main | чтение workflow; остаточный риск |
| Копии | I | чтение копии посторонним | шифрование AES-256 / RSA-4096, ключи вне GitHub | T-44, T-50 |
| Копии | D | потеря копий/ключа | две независимые линии копий, ключи у владельца | T-44, T-50; «Нужно от владельца» |
| WhatsApp | I | передача номера и времени пациента в WhatsApp | только по нажатию сотрудника | чтение кода; остаточный риск (DATA_MAP) |
| Аккаунты владельца | S/E | захват GitHub/Supabase | 2FA, второй администратор | не проверено (нет доступа к настройкам аккаунтов); «Нужно от владельца» |
