# ADMIN_GUIDE — руководство администратора и эксплуатанта

## 1. Учётные записи и роли
- Регистрация закрыта. Новый сотрудник: Supabase Dashboard → Authentication → Users → Add user (почта + пароль). В приложении есть ссылка «Hesab yarat və ya sil».
- Роль назначает админ в приложении: настройки → «Сотрудники» (владелец, админ, агент, специалист; специалист привязывается к своей колонке). Пока роли нет, аккаунт ничего не видит (проверено: X-30, X-31, X-34).
- Удаление сотрудника: роль снимает админ; аккаунт удаляется в Supabase. Записи, которые он сделал, остаются (автор виден в журнале).
- Цены и длительности, которые подставляются в новую запись: Ayarlar → Mütəxəssislər → «Yeni qəbul: qiymət və müddət» (только админ; меняется в журнале).
- Двухфакторного входа нет — по решению владельца (RISK_REGISTER.md, S-02).

## 2. Ежедневно и еженедельно
| Когда | Что | Где |
|---|---|---|
| каждый день | ночные копии прошли (зелёные), нет копий с пометкой UNVERIFIED | GitHub → Actions → Database backup; письма GitHub о падении |
| раз в неделю | скачать последний архив `ruqya-backup-*.tar.gpg` и положить в 2 места вне GitHub | docs/BACKUP.md |
| раз в месяц | учения DR: `node tools/dr_drill.js` по свежей DR-выгрузке | DISASTER_RECOVERY.md |
| при падении копии | открыть упавший шаг; если обновился сервис входа Supabase — B-16/S-08 в RISK_REGISTER.md | backup.yml |
Пароль копий (`BACKUP_PASSPHRASE`) и закрытый ключ DR (`dr_private.pem`) хранятся только у владельца, вне этого ПК и GitHub.

## 3. Публикация новой версии
```bash
git checkout main && git pull
node tests/lint.js && node tests/run.js        # все тесты должны пройти
sh publish.sh "что изменено"                    # штамп версии, CSP, проверка секретов, push → GitHub Pages за минуту
```
`publish.sh` откажется: не на main; main отстаёт от GitHub; есть новые файлы, не добавленные в git; найден секрет. Открытые копии приложения сами перезагрузятся на новую версию. APK собирается автоматически при изменениях в `android/`.

## 4. Изменения базы
Миграции — `sql/2026-11-*.sql`, у каждой `sql/rollback-*.sql`. Применять в SQL Editor Supabase (или коннектором) **после свежей копии** (Actions → Database backup → Run). Установка с нуля: `db/schema_live_20261116.sql`, затем `sql/2026-11-realtime.sql`, затем миграции из списка `AFTER` в `tests/dbcopy.js` по порядку. Проверка после изменений: `node tools/schema_check.js` с новым слепком структуры и Supabase → Advisors (0 ERROR).

## 5. Запросы людей о своих данных (выгрузка и удаление)
Выгрузка всего о пациенте по ключу (владелец, SQL Editor) — запрос в `tests/t/97-person-export-delete.js` (раздел «export»): все записи пациента и все записи журнала о них. Удаление — в карточке пациента «Pasiyentin məlumatını sil» (рус. «Удалить данные пациента») (функция `ruqya_anonymize`: имя, телефон и заметки стираются во всех записях и в журнале). Проверено на копии: после удаления поиск по всем текстовым полям всех таблиц ничего не находит (тест 97). Что и где хранится — DATA_MAP.md.

## 6. Переезд, сбои, замена ключей
DISASTER_RECOVERY.md: сценарии A–E, таблица мест с адресами и ключами, порядок замены каждого ключа. Свой сервер: `deploy/nginx.conf`.

## 7. Наблюдение
- Supabase → Logs (хранятся ≈ 1 сутки на бесплатном тарифе): ошибки API и базы. Персональных данных в журналах нет (evidence/stage5/pii-in-logs.txt).
- Журнал изменений в приложении — кто что изменил или удалил; правка журнала запрещена всем ролям (проверено матрицей доступа).
