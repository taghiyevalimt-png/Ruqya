# Mərkəz (Ruqya) — правила работы для Claude

Приложение записи центра руқьи/хиджамы (Баку). Устройство проекта — HANDOFF.md; изменения — CHANGELOG.md; риски — RISK_REGISTER.md.

## Обязательный порядок после КАЖДОГО изменения (указание владельца 23.11.2026)
Не говорить «готово / исправил / добавил», пока не пройдены все шаги:

1. **Тест на само изменение.** Новый или обновлённый тест в `tests/t/` (имя `99-<дата>-<что>.js`); проверить, что на старом коде он падает, на новом — проходит.
2. **Все тесты целиком**, а не только связанные: `cd tests && node run.js` (с базой: `RUQYA_PG_PORT=<порт> node run.js` на запущенном PostgreSQL; см. HANDOFF.md). Допустимы только известные пропуски среды: `24-aria` (нет axe-core), `91-schema` (нужен PostgreSQL 17). Любое другое падение — исправить до публикации.
3. **Общая проверка приложения и возможных ошибок:** `node --check` скрипта, ES5 (`11-es5`), CSP (`python3 tools/csp.py --check`), русские тексты без дублей ключей в словаре RUD (дубль ключа ломает старые Android в strict mode), вид на экране (скриншоты светлой/тёмной темы, az/ru) для изменённых экранов; для базы — сухой прогон миграции в транзакции с откатом, права ролей, `get_advisors` (security, performance) без новых замечаний; для Android — компиляция и отрисовка образцов, затем GitHub Actions «Build APK» и «Widget check» (запускаются сами при изменении `android/**`) — оба зелёные, картинки в ветках `checks-23` / `checks-33` просмотрены.
4. **Публиковать самому**, не спрашивая: `sh publish.sh "сообщение"` (веб → GitHub Pages; изменения `android/**` → новый APK). Миграции базы — коннектором Supabase, с файлом отката в `sql/rollback-*`.
5. **Проверить живую версию:** `version.txt` на сайте = новой версии, страница открывается без ошибок в консоли; для Android — сборка APK «completed successfully» и последний релиз = новый номер.
6. **Только после этого** коротко отчитаться и всегда дать ссылки для установки:
   - Android (APK): https://github.com/taghiyevalimt-png/Ruqya/releases/latest/download/Ruqya.apk
   - iPhone: https://taghiyevalimt-png.github.io/Ruqya/ — открыть в Safari → «Поделиться» → «На экран Домой»
   - Компьютер: та же ссылка в браузере.

## Логика статистики (указания владельца — не менять без него)
- «Yazdı» и «Kim neçə seans yazıb» — по дню, когда запись **написана** (created_at, время Баку), а не по дню сеанса: написал сегодня запись на завтра или на следующую неделю — это «сегодня», особенно в «Bu gün» (24.11). Отменённые тоже считаются написанными (23.11).
- «Uğurlu» — не отменённые сеансы, чей день в периоде и которые уже закончились; «Ləğv» — отменённые («Ləğv» / «Gəlmədi») по дню сеанса.
- Неделя — пятница–четверг; месяц — с первой пятницы до дня перед первой пятницей следующего месяца.
- Товары: «Payı» агенту — с его продаж; специалисту — с продаж его пациентам; «Keçici» — специалистам ничего.
- Постоянная проверка: tests/t/99-1123-stats-oracle.js (независимый расчёт), 99-1124-written-today.js.

## Важное
- Веб — один файл `index.html`, ES5 без сборки. Новые запросы в `refresh()` не добавлять в конец списка (там читаются `res[res.length-N]`).
- Не запускать заново старые миграции, которые создают `public.ruqya_*` помощники RLS (они живут в схеме `private`).
- Репозиторий публичный: никаких секретов; `publish.sh` проверяет это сам.
