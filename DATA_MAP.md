Источник: схема живой базы `db/schema_live_20261116.sql` (выгрузка 16.11.2026), код `index.html`, задания `.github/workflows/*`. Физическое место базы: Supabase, регион Европа (проект `ldkhdeehrrajvgrtieal`; точный дата-центр виден владельцу в панели Supabase → Project Settings → General, в этой среде не проверено). Хостинг страницы: GitHub Pages (CDN GitHub/Fastly). Резервные копии: GitHub Actions artifacts (США, инфраструктура GitHub) — зашифрованы; DR-выгрузки — дополнительно у владельца.

## Куда данные уходят наружу
- Supabase (база, вход, Realtime) — `connect-src` CSP разрешает только адрес проекта (проверено T-47).
- WhatsApp / звонок: только по нажатию сотрудника, через ссылки `wa.me` и `tel:` (номер в адресе ссылки — это передача номера в WhatsApp, по действию пользователя).
- Аналитики, внешних шрифтов, CDN нет (проверено T-47: `evidence/stage0/baseline/live-network.json`).

## Что остаётся после удаления данных пациента (обязано остаться)
Строки сеансов с датой, временем, специалистом, ценой и автором записи; имя заменено на «Anonim», телефон и заметка пусты; одна строка журнала «ANON» с числом записей (без данных пациента). Копии в резервных архивах — до истечения их срока (35 и 7 дней).
